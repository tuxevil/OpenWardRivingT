# 0002 — Bearer token auth with `?token=` fallback

- **Status:** Accepted
- **Date:** 2025-06-16
- **Deciders:** @tuxevil

## Context

The CGI dispatcher at `openwrt_files/www/cgi-bin/wardriving_api`
exposes a wide surface (`status`, `start`, `stop`, `set_hw`,
`set_mode`, `delete_file`, `upload_tiles`, `upload_potfile`,
`pwnagotchi_sync`, `replay_*`, etc.) and runs as `root` on the router.
Every action except `action=status` must be authenticated. The token is
generated by `install.sh:60` and stored at `/etc/wardriving_api_token`
(mode `0600`).

Two competing concerns shape the auth design:

1. **Operational**: scripts (`run_hashcat.sh`), `wget` invocations, and
   `window.open()` downloads cannot set custom HTTP headers, so a
   pure-header scheme breaks them.
2. **Operational-security**: query strings land in `uhttpd` access
   logs, in shell history, and in the `Referer` header of outbound
   requests. A pure-query scheme leaks the token to anywhere a
   downloaded file is later uploaded.

A previous version of the dashboard occasionally fired raw
`fetch('/cgi-bin/wardriving_api?action=…')` calls, which silently 401'd
and produced "frozen UI" bugs (most notably a stuck *Stop* button).

## Decision

- The CGI accepts `Authorization: Bearer <token>` (case-insensitive
  header) as the **preferred** authentication method. The token is
  read from the `WARDRIVING_TOKEN_FILE` (default
  `/etc/wardriving_api_token`).
- The CGI also accepts `?token=…` (and `?token=<token>` from
  `Content-Type: application/x-www-form-urlencoded` bodies) as a
  **fallback** for `window.open()` downloads, scripts, and legacy
  clients. The fallback is documented in
  [README.md → API & security](../../README.md#api--security).
- `action=status` is the **only** public (token-free) endpoint. The
  attack-surface trade-off is documented in
  [CONTEXT.md → Security patterns](../../CONTEXT.md).
- The dashboard's `apiUrl()` and `apiJson()` helpers in
  `openwrt_files/www/wardriving/app.js` attach the Bearer header
  automatically and append `?token=…` as a second copy. Raw
  `fetch('/cgi-bin/wardriving_api?…')` calls in the dashboard are a
  regression and are caught by review.
- The dispatcher sources `common.sh`, which owns the central
  `is_protected_action` predicate. New actions are protected by
  default; making one public requires editing `is_protected_action` and
  updating the README.

## Consequences

- **Easier:** Scripts, downloads, and modern dashboard code share the
  same token without manual header plumbing. Operators can copy a
  download URL with `?token=…` into a browser without losing auth.
- **Harder:** The query-string path is a permanent low-grade leak
  vector. We mitigate by recommending a LAN-only deployment
  (uhttpd never reaches the WAN) and by warning against pasting
  dashboard URLs with the token into public bug reports.
- **Trade-off:** Two auth paths to test. The
  [test suite](../../test/run_tests.sh) covers both the Bearer header
  and the `?token=` query in CGI contract tests.
- **Follow-up:** A future revision could move the dashboard fetch
  override to a `Credentials`-style cookie once the project is willing
  to give up the `window.open()` download ergonomics. That would be a
  new ADR, not a silent change.
